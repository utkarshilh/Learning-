## 1. What is Versioning & Why Do We Need It?

**Problem without versioning:**
- S3 keeps only **one copy** of each object key by default
- If you upload `customers.csv` again → it **overwrites** the existing file
- Accidental upload with wrong data → original is lost → Spark jobs / Redshift COPY fail
- No way to recover the original

**Solution — Versioning:**
- Keeps **multiple versions** of the same object
- Each upload of the same filename creates a **new version** instead of overwriting
- Version IDs are **automatically generated by S3** — no manual action needed

**3 Main Use Cases:**
| Use Case | Description |
|---|---|
| **Accidental Upload** | Wrong file uploaded with correct name → old version still accessible |
| **Accidental Delete** | Deleted an object → can restore from an older version |
| **Historical Purposes** | Track changes over time (e.g., Python scripts, config files) |

---

## 2. How Versioning Works

- Versioning is enabled at the **Bucket level** → applies to **all objects and folders** inside that bucket
- Objects uploaded **before versioning was enabled** get version ID = `null`
- Objects uploaded **after enabling** get an auto-generated version ID (alphanumeric string)
- You can:
  - **List** all versions of an object
  - **Download** a specific version
  - **Delete** a specific version (other versions remain intact)
- ⚠️ Deleting the **object** from the bucket (not a specific version) → **all versions are deleted**
- Always delete **individual versions**, not the whole object, if you want to keep history

---

## 3. Hands-On — Console

**Enable versioning:**
`Bucket → Properties → Bucket Versioning → Edit → Enable → Save`

**Also available:** MFA Delete (requires multi-factor auth before deleting) — not enabled in demo

**Working with versions in console:**
- Click on an object → **Versions tab** → shows all versions with timestamps
- Can **download** or **delete** individual versions from here
- Copying the S3 URI of a version still gives the same object URI — version ID is **not embedded** in the URI shown in console

---

## 4. Hands-On — CLI

Use `aws s3api` (not `aws s3`) for version-related operations.

### List all versions of objects in a bucket:
```bash
aws s3api list-object-versions --bucket 3am-s3-bucket
```
Returns all objects and their versions (newest to oldest), with version IDs and last modified timestamps.

### Delete a specific version:
```bash
aws s3api delete-object \
  --bucket 3am-s3-bucket \
  --key orders_streaming_file.csv \
  --version-id <version-id>
```
Only that specific version is deleted — object and other versions remain.

---

## Key Takeaways

- Versioning is **disabled by default** — must be explicitly enabled at bucket level
- Once enabled, every upload of the same filename = **new version**, not an overwrite
- S3 auto-generates version IDs — you don't need to manage them
- Pre-versioning objects get version ID = `null`
- Use **`aws s3api`** (not `aws s3`) for all version-related CLI operations
- Delete individual versions carefully — deleting the whole object removes **all versions**
- Great protection against accidental overwrites and deletes
